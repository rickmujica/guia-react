## De Express 4 a Express 5

Express 5 (estable desde 2024) es casi igual. Lo que cambió y vas a notar en un proyecto viejo:

| | Express 4 | Express 5 |
| --- | --- | --- |
| Errores en rutas async | Hay que atraparlos y llamar a `next(error)` (o usar `express-async-errors`) | Express los pasa solo al manejador de errores |
| Comodines en rutas | `app.get('*', ...)`, `'/archivos/*'` | Con nombre: `'/*todo'`, `'/archivos/*ruta'`; opcionales con llaves: `'/ofertas{/:id}'` |
| `req.query` | Se podía reasignar | De solo lectura (un getter) |
| `req.body` sin parser | `{}` | `undefined` |
| Métodos viejos | `res.send(status)`, `res.json(obj, status)`, `req.param()`, `app.del()` | Eliminados: `res.status(201).json(obj)` |
| `res.redirect('back')` | Existía | `res.redirect(req.get('Referrer') ?? '/')` |
| Query anidada (`?a[b]=1`) | Se parseaba por defecto | No, salvo `app.set('query parser', 'extended')` |
| Node mínimo | 0.10 | 18 |

## Preguntas de entrevista

<Entrevista title="Node.js">

- **¿Qué es Node?** Un entorno para ejecutar JavaScript fuera del navegador: el motor V8 más libuv, que le da I/O asincrónico (archivos, red, timers).
- **¿Es single-threaded?** Tu JavaScript corre en un solo hilo; el I/O lo hacen el sistema operativo y el thread pool de libuv. Para CPU pesado: worker threads.
- **¿Qué es el event loop?** El mecanismo que ejecuta los callbacks pendientes (timers, I/O, setImmediate) de a uno cuando el call stack está vacío. Entre cada uno se vacían las microtareas (promesas, nextTick).
- **¿Qué bloquea el event loop?** Código sincrónico largo: cálculos pesados, las funciones `Sync`, `JSON.parse` de algo enorme, regex catastróficas.
- **¿process.nextTick vs setImmediate vs setTimeout(0)?** nextTick corre antes de seguir con el loop (junto con las microtareas); setTimeout(0) en la fase de timers; setImmediate en la fase check, después del I/O.
- **¿CommonJS vs ES modules?** `require`/`module.exports`, sincrónico, vs `import`/`export`, el estándar, con top-level await y análisis estático.
- **¿Qué es un stream?** Datos procesados de a pedazos sin cargar todo en memoria; se conectan con `pipeline`, que maneja errores y backpressure.
- **¿Qué es un EventEmitter?** Un objeto que emite eventos con nombre a los que se suscriben oyentes; la base de streams, servidores y procesos.
- **¿dependencies vs devDependencies?** Las que se necesitan para correr vs las que solo se usan para desarrollar (tipos, tests, build).
- **¿Para qué es el package-lock.json?** Fija la versión exacta de todo el árbol de dependencias, para que todos (y el CI) instalen lo mismo.
- **¿Cómo usás todos los núcleos?** Varios procesos: cluster, PM2 o varias réplicas del contenedor detrás de un balanceador.

</Entrevista>

<Entrevista title="Express y APIs">

- **¿Qué es un middleware?** Una función `(req, res, next)` en la cadena del pedido; responde o llama a `next()`. Los de error tienen 4 parámetros.
- **¿params, query y body?** Segmentos de la ruta, lo que va después del `?`, y el cuerpo (con `express.json()`). Todo viene del cliente: se valida.
- **¿PUT vs PATCH?** PUT reemplaza el recurso entero (idempotente); PATCH cambia una parte.
- **¿401 vs 403?** 401: no sé quién sos (falta o es inválido el token). 403: sé quién sos y no tenés permiso.
- **¿Qué es CORS?** Una protección del navegador: solo deja que una página lea respuestas de otro origen si el servidor lo autoriza con `Access-Control-Allow-Origin`.
- **¿Sesiones o JWT?** Sesión: el servidor guarda el estado, fácil de revocar. JWT: firmado, sin estado, difícil de revocar, por eso vida corta. En web, en cookie `httpOnly`.
- **¿Cómo se guardan las contraseñas?** Con un hash lento y con sal: bcrypt, argon2 o scrypt.
- **¿Cómo estructurás una API?** Por feature y en capas: rutas, servicio, repositorio, con las dependencias inyectadas.
- **¿Cómo manejás los errores?** Errores de negocio con su status, un único middleware que los traduce, un 500 genérico para lo inesperado y el detalle en los logs.
- **¿Cómo la testeás?** Unit tests de los servicios con mocks; integración con supertest o `listen(0)` y `fetch`.
- **¿Qué hacés en un deploy?** Variables validadas, logs estructurados, apagado prolijo con SIGTERM, health check, `npm ci --omit=dev`, `NODE_ENV=production`.

</Entrevista>
